# EHTID Game Lab · Alpha 0.4.7

Инструмент для локальных игровых файлов и одиночных игр на **Windows x64 и Android**. Тёмно-фиолетовый интерфейс, оригинальная иконка EHTID, редактор сейвов и экспериментальные читы Windows.

## Скачать: GitHub Releases

**[Скачать последнюю сборку для Windows и Android](https://github.com/craftkot/Hik/releases)**

Сборки опубликованы на странице **Releases**, а **не в Actions / Artifacts**. Скачивание файлов релиза не требует поиска запуска CI и не зависит от 30-дневного срока хранения временных артефактов. Каждый выпуск создаётся после успешных проверок Android и Windows.

- **Windows:** скачай `EHTID-GameLab-Windows-x64-v<версия>.zip`. Распакуй весь ZIP в папку и запусти `game_lab.exe`. Внутри есть `EHTID-Overlay.exe`, `EHTID-MemoryHelper.exe`, Flutter-библиотеки, иконка и русская инструкция `START_HERE_RU.md`.
- **Android:** скачай напрямую `EHTID-GameLab-Android-v<версия>.apk`, установи на телефон и прочитай приложенную инструкцию `EHTID-Android-Instruction-RU.md`. Системное разрешение на оверлей даётся отдельно по запросу.
- **SHA-256:** сравни хеш скачанного APK/ZIP с `SHA256SUMS.txt` в Assets релиза.

Каждой публикации соответствует **неизменяемый тег** (например `v0.4.7-alpha.1`). Новый код выпускается с новым номером версии; уже опубликованные APK и ZIP не перезаписываются.

## Возможности

**Редактор сейвов (Windows + Android).** Поиск файлов и чисел по выбранным папкам. Работа с текстом и JSON, точечный бинарный редактор Int32/Float32 (LE/BE), проверки перед записью и резервные копии. На Windows предложены стандартные каталоги AppData, Saved Games и Documents. Android использует системный SAF-picker; при работе с несколькими выбранными папками каждый файл сохраняет привязку к своей папке. Шифрованные/сжатые форматы нельзя гарантированно изменить.

**Windows RAM-читы — только локальные одиночные игры.** Выбор видимого процесса, поиск Int32/Int64/Float32/Float64 по доступной памяти, постепенное уточнение адресов, фильтры **изменилось / не изменилось / увеличилось / уменьшилось**. Изменяется только выбранный адрес, после проверки старого значения, подтверждения и контрольного чтения. Есть условный откат последнего изменения.

**Оверлей Windows.** Компактный `EHTID-Overlay.exe` поверх оконных и безрамочных игр. Нажатие на HP в самой игре пока не изменяет RAM автоматически: сначала нужно найти и подтвердить адрес. В эксклюзивном fullscreen панель может не отображаться.

**Android-оверлей.** Перемещаемый значок и ввод видимого числа, переход к поиску в доступных файлах игры. Это **не RAM-редактор Android** — обычный APK не имеет доступа к памяти других приложений. Android может ограничивать оверлей поверх защищённых окон и доступ к приватным каталогам игр.

## Сборка и выпуск

Исходники Flutter находятся в `lib/`, Android SAF/оверлей — в `android_native/`, Windows memory helper и WinForms-панель — в `tool/`. Workflow `.github/workflows/build.yml` запускает Flutter analyze и тесты, собирает APK/Windows portable, выполняет selftest Windows helper, проверяет содержимое архивов и **после успешных Android + Windows jobs на ветке main** публикует новый GitHub Release. Публикации из PR не выполняются.

Для нового релиза подними поле `version:` в `pubspec.yaml`, обнови `docs/RELEASE_NOTES_RU.md` и объедини проверенный PR в main. Если выпуск с таким тегом уже существует, workflow не заменит файлы.

## Ограничения и безопасность

Альфа-версия не гарантирует поддержку конкретной игры. Сделай копии локальных сохранений и не меняй значения, которые ещё записывает запущенная игра. Нет обхода античита, DRM, sandbox и серверных данных; онлайн-читы не поддерживаются. Скриншот/OCR может предоставить только числовой кандидат, а не достоверный адрес памяти. Тестирование на конкретном Windows-ПК или Android-устройстве проводится отдельно от CI.


## Безопасная запись сейвов (Alpha 0.4.3)

Windows теперь создаёт проверенную резервную копию, записывает новую версию в отдельный временный файл, сверяет исходные данные повторно и только потом подменяет файл. Если ошибка возникла после перемещения оригинала, приложение пытается восстановить его и проверить восстановление. Для Android редактор передаёт исходные байты и проверяет их повторно через системный SAF-провайдер перед записью. Служебные файлы EHTID исключаются из поиска.

**Важно:** Windows использует восстанавливаемую последовательность переименований, а не гарантированно атомарную подмену. При отключении питания между этапами останется файл `.ehtid-rollback-*.tmp`, из которого можно вручную восстановить исходный сейв. Существующие `.ehtid-backup-*.bak` никогда не удаляй, пока не проверишь, что игра загрузила новое сохранение.

**Следующий этап разработки:** доведение читов и сейв-редактора до стабильной версии, затем отдельная работа над переводчиком игровых ресурсов.

## Восстановление через интерфейс (Alpha 0.4.4)

В Windows открой сейв в разделе «Редактор сохранений» и нажми кнопку «Восстановить резервную копию». Появятся бэкапы только этого файла; после предпросмотра восстановление требует отдельного подтверждения. Перед откатом создаётся новая копия текущего файла. Изменения исходного сейва и бэкапа после предпросмотра приводят к отмене операции. При обнаружении аварийной копии `.ehtid-rollback-*.tmp` автоматическое восстановление блокируется, пока ситуация не будет разобрана вручную. На Android восстановление из бэкапа через UI ещё не поддерживается.

## Поиск важных игровых значений (Alpha 0.4.5)

В Windows и Android при просмотре JSON-сейва через редактор полей сначала выводятся **валюта, HP, мана, характеристики, уровень, опыт и ресурсы**, распознанные по именам ключей (русские/английские). Они подсвечиваются фиолетовым. Затем следуют обычные данные в прежнем порядке. В общем поиске чисел сначала показываются результаты с явным ключом вроде `coins=100` или `"health":100`. Файлы с понятными названиями также поднимаются в списке. Подсказки не являются подтверждением назначения игрового поля; бинарные значения без семантических метаданных автоматически не угадываются. Сортировка не изменяет сейв.


## Фильтры важных полей (Alpha 0.4.6)

В окне «Редактировать поля JSON» появились фильтры **«Только важные»**, категории **«Валюта», «HP/здоровье», «Мана/MP», «Характеристики», «Уровень», «Опыт», «Ресурсы»** и поиск по имени ключа или его значению. Фильтры работают на Windows и Android и не затрагивают сохранения до отдельного подтверждения изменения. Поиск проверяет до 2500 считанных полей, а список одновременно показывает до 500 результатов; запрос позволяет найти и более поздние поля. «Сбросить фильтры» возвращает полный список. Для локализационных JSON доступен поиск по ключам без игровых категорий. Назначение поля предполагается по имени, не подтверждается автоматически.


## Чтение текущих показаний RAM без записи (Alpha 0.4.7)

После первого поиска HP/валюты в одиночной игре Windows нажми **«Обновить показания»**. Модуль **только читает** значения всех ранее найденных доступных адресов и отображает их рядом с адресами. Никакой записи, автоматического закрепления числа или нового поиска всего процесса нет; недоступные и некорректные числа исключаются. Можно повторять по запросу, сравнивая результат с игрой. В плавающей Windows-панели выбери «Обновить показания» и нажми «Обновить / сравнить». Перезапуск процесса может сделать прежние адреса недействительными — после этого начни новый поиск.

## Android: выбор установленной игры (готовится к выпуску)

В Android-панели редактора появится кнопка **«Игра»**: список установленных приложений с поиском по названию и имени пакета. После выбора EHTID сканирует **только ранее разрешённые пользователем SAF-папки**, сопоставляя пути с названием и package ID игры. Совпадения — кандидаты, а не подтверждённые сейвы. В списке редактора видны все найденные файлы, чтобы не скрывать сейвы с нестандартными расширениями. Кнопка папки остаётся запасным ручным режимом.

Выбор приложения **не открывает** его закрытые каталоги `/data/data`, `Android/data` или `Android/obb`. Если доступ к публичным папкам ранее не давался или игра хранит файлы только в приватной области, автоматический поиск вернёт пустой список и объяснит ограничение. Для поиска не требуется `QUERY_ALL_PACKAGES` или доступ ко всей памяти устройства. До отдельного релиза функция находится в рабочей ветке.
