# EHTID Game Lab 0.4.17 Alpha — проверка диапазона Float32/Float64

Windows RAM: при ручном вводе ненулевые числа, которые превращаются в ноль при разборе Float64 или округлении Float32, теперь отклоняются. Настоящий ноль и представимые субнормальные значения остаются допустимыми. Добавлены регрессионные тесты для обоих знаков, Float32 и Float64. Изменения не добавляют автоматических записей памяти.

# EHTID Game Lab 0.4.16 Alpha — глубокий поиск RAM на Windows

## Режим поиска по каждому байту

Раньше первый поиск HP, денег, маны или других чисел в памяти Windows проверял в основном адреса, **выровненные по ширине значения**: каждые четыре байта для Int32/Float32 и каждые восемь для Int64/Float64. Некоторые игровые движки хранят числа внутри упакованных структур — на невыравненных адресах. В таких случаях EHTID мог показывать «Совпадений нет», даже если значение в открытой памяти процесса присутствовало.

**Теперь в «Читы (соло) → Live Memory» есть переключатель «Глубокий поиск · каждый байт».**

Как использовать:
1. Открой свою **одиночную офлайн-игру** и выбери видимый процесс через «Найти окна».
2. Введи текущее значение (например, 120), выбери тип Int32/Int64/Float32/Float64.
3. Сначала попробуй **обычный первый поиск** — он заметно быстрее.
4. Если обычный поиск не находит нужное число, включи **«Глубокий поиск · каждый байт»**, затем заново нажми «Первый поиск».
5. EHTID проверит каждое байтовое смещение внутри ограниченного объёма доступной памяти процесса и покажет кандидатов. Для глубокого режима лимит — **512 МиБ**, для обычного остаётся до **2048 МиБ**.
6. Когда значение в игре изменится, продолжай пользоваться кнопками «Уточнить», «Обновить показания», относительными фильтрами, звёздочками наблюдения и ручной записью с подтверждением.

### Безопасность, нагрузка и ограничения
- Режим **не отключает античит, DRM или защиту процесса**, не внедряет код и не получает дополнительные системные права. Читает только память доступного Windows-процесса.
- Глубокий поиск требует больше CPU, поэтому он ограничен 512 МиБ за проход и максимум 3000 результатов на первый поиск по умолчанию. Если лимит результатов достигнут, уточни число или попробуй более редкое значение.
- Смена режима стирает **текущие кандидаты и их снимки**, а также сбрасывает список наблюдения, чтобы не смешивать адреса двух разных поисков. Никакие игровые данные при переключении не изменяются.
- Уточнение выбранных адресов после первого поиска выполняется как раньше; режим по каждому байту влияет **только на первичный поиск**.
- Невыравненный адрес сам по себе не подтверждает, что найдено игровое HP или валюта. Меняй только проверенный вручную адрес в собственной офлайн-игре, с подтверждением перед записью.
- Некоторые игры используют сжатые, зашифрованные, динамические или серверные значения. Доступность конкретной игры не гарантируется.
- Изменение сделано **для Windows**; Android-разработка в этой версии не продолжается.

## Тестирование

Добавлены тесты ограничений параметров поиска, видимого переключателя режима и передачи параметра сканеру. В собственный Windows memory helper добавлена проверка упакованного значения по смещению +3, выровненного значения, чтения через границу чанка и исключения дублирующихся адресов. Старый self-test чтения, защищённой записи, обратного чтения и отката сохранён.

## Установка

Скачай полный **Windows x64 portable ZIP** на [странице релизов](https://github.com/craftkot/Hik/releases), распакуй и запусти `game_lab.exe`. В той же папке останутся `EHTID-MemoryHelper.exe` и `EHTID-Overlay.exe`. Обновление не требует удалять старые сейвы; собственные резервные копии файлов игры сохраняй отдельно.
